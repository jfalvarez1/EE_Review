Prototyping Best Practices

Effective prototyping accelerates development and catches issues early. From breadboards to first PCB spins, understanding each prototyping stage's strengths and limitations helps engineers choose the right approach for each design phase.

Goal
Validate design before production investment
Key Principle
Prototype only what needs validation

Prototyping Stages

Stage Method Purpose Limitations
Concept Simulation (SPICE, LTspice) Validate circuit topology Parasitics not modeled
Proof-of-concept Breadboard / dead-bug Quick functional test Poor for RF, high-speed
Development Protoboard / perfboard Semi-permanent test fixture No ground plane
Pre-production PCB prototype (OSHPark, JLCPCB) Validate final layout 2-4 week lead time
Production validation Small production run Manufacturing process validation Tooling investment

Breadboard Guidelines

Breadboard Parasitics: Each row has ~2pF capacitance and ~25nH inductance. At 10MHz, this becomes significant. Limit breadboard use to ≤1MHz for analog or ≤5MHz for digital.

Dead-Bug and Manhattan Style

For RF and high-frequency prototypes where breadboards fail:

Dead-Bug Style
IC upside-down, wires soldered directly to pins
Manhattan Style
Components on copper islands on ground plane PCB
Technique Frequency Range Advantages
Dead-bug DC - 500MHz Quick, minimal parasitics, good ground
Manhattan DC - 1GHz+ Excellent ground, reproducible
Copper tape DC - 100MHz Easy to modify, visual

PCB Prototype Considerations

Design-for-Debug Feature Purpose
Test points Easy scope/meter access to critical nodes
0Ω resistor jumpers Option to cut/bridge connections
DNP component pads Space for filter components if needed
Header for power External supply during bring-up
LED indicators Quick visual status feedback
Spare GPIO broken out Debug signals, test fixtures
First Spin Strategy: Always add more test points than you think necessary. You cannot probe a node that isn't accessible. Plan for failure modes.

Bring-Up Procedure

Systematic board bring-up prevents damage and identifies issues early:

  1. Visual Inspection: Check for solder bridges, missing components, wrong orientation
  2. Power Rail Check: Measure resistance to ground before applying power (should not be near-short)
  3. Current-Limited Power: Apply power with 50-100mA limit initially
  4. Voltage Verification: Check all power rails are correct before proceeding
  5. Clock/Oscillator: Verify crystal/oscillator is running
  6. Processor Alive: Check for debug interface response
  7. Peripheral Test: Test each subsystem individually
  8. Integration Test: Full system operation
Document Everything: Keep a bring-up log noting measurements, issues found, and modifications made. This is invaluable for future revisions.

Common Prototype Issues

Issue Symptom Check
Solder bridge Short circuit, high current Visual inspection, continuity test
Cold solder joint Intermittent behavior Touch-up all suspicious joints
Wrong component value Circuit works but off-spec Verify with multimeter
Missing decoupling cap Noise, instability, random resets Add 100nF ceramic at IC VDD
Ground bounce Digital noise on analog signals Separate analog/digital grounds
Reversed polarity Component damage, no function Check diodes, electrolytics, ICs
