SPI Daisy Chaining

SPI daisy chaining reduces GPIO requirements by connecting multiple devices in series. Data shifts through each device sequentially, requiring careful timing and understanding of the shift register behavior.

Single CS
One chip select for all devices
Data Flow
MOSI → D1 → D2 → ... → MISO
Clock Cycles
N devices × bits per device
Latency
All data shifted before latch
Key Insight: In daisy chain mode, each device's DOUT connects to the next device's DIN. Data for the last device in the chain must be sent first, as it shifts through all preceding devices. The total transaction requires N × (bits per device) clock cycles.

Daisy Chain Topology

Daisy Chain vs Individual CS

Aspect Daisy Chain Individual CS
GPIO Pins 1 CS total N CS pins needed
Update Speed Slower (all data shifts) Faster (selective update)
Flexibility Must update all devices Update any device individually
Wiring Series connection, cleaner Star topology, more traces
Fault Tolerance One failure breaks chain Independent operation
Device Support: Not all SPI devices support daisy chaining. Check that the device has a DOUT or SDO pin that can be connected to the next device's DIN. Some devices only have SDO for read-back, not pass-through.
