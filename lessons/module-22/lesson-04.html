Testing and Fixing Monotonicity Issues

Learn practical methods to detect non-monotonic behavior in data converters and techniques to mitigate these issues in real designs.

Key Insight: Non-monotonic behavior often goes undetected until a control system fails in the field. Proactive testing using histogram methods (for ADCs) or servo-loop tests (for DACs) during design validation can catch these issues early. When guaranteed monotonicity is required, select converters that specify "monotonic by design" or "DNL < ±1 LSB guaranteed."

Mitigation Strategies

Strategy When to Use Effectiveness Tradeoffs
Select Guaranteed Monotonic Part New designs, critical applications Best May cost more, fewer options
Signal Averaging ADC with missing codes Good Reduces bandwidth, adds latency
Dithering DAC in audio or measurement Moderate Adds noise floor, complexity
Calibration SAR/Pipeline ADCs with cal input Good Requires cal procedure, storage
Use Sigma-Delta When speed allows Best Lower speed, latency
Software Compensation Known bad codes, static systems Moderate Requires characterization per unit
Signal Averaging Can Hide Missing Codes:

Averaging multiple ADC samples is a powerful technique that can effectively "recover" missing codes:
  • If code N is missing but N-1 and N+1 exist, averaging will produce N
  • This works because noise causes samples to occasionally hit adjacent codes
  • 4x averaging reduces missing code impact by ~6dB
  • 16x averaging can fully eliminate most missing code effects

However: This doesn't fix the underlying issue and adds latency. For control loops, the delay from averaging may cause instability. Use averaging for measurement, not control.
